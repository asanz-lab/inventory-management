Factory Inventory Management — Architecture

A demo full-stack application for factory operations: inventory tracking, order management, demand forecasting, and spending analytics. Vue 3 single-page app on the front, FastAPI service on the back, JSON files on disk as the source of truth. No database.

Tech Stack

Frontend
Vue 3 + Vite
Composition API, Vue Router, Axios. Dev server on port 3000.
Backend
Python FastAPI
Pydantic models, Uvicorn ASGI server. Port 8001.
Data Layer
JSON files
Loaded into memory at startup via mock_data.py. No persistence.
Internationalization
Custom composable
useI18n.js with English and Japanese locale files.
Testing
pytest + TestClient
Backend tests in tests/backend/, ~51 tests covering endpoints.
Tooling
npm + uv / pip
Vite build for the client, Python venv with FastAPI/Pydantic/Uvicorn.

Key Conventions

Single filter contract. Four optional query params — warehouse, category, status, month — flow from the Vue UI through useFilters.js into api.js and on to the FastAPI route. The string "all" means "no filter" on every parameter; the backend skips the predicate when it sees it.

Time filtering. month accepts both a direct match (2025-03) and a quarter shorthand (Q1-2025). Quarter codes are expanded via QUARTER_MAP in main.py. Inventory has no time dimension and therefore ignores the month filter.

Validation at the edge. Every list endpoint declares response_model=List[…] so Pydantic serializes the in-memory dicts into typed JSON. Adding a field to the JSON fixtures requires updating the matching Pydantic model.

Reactive layering on the client. Raw API data lives in ref()s; everything the template binds against is a computed() derived from those refs plus the current filter state. This keeps chart calculations cached until inputs change.

State is in-memory only. The server reloads JSON on every restart. Mutations performed through the task and purchase-order endpoints survive only for the lifetime of the Python process.
